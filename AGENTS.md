# Photochem — Project Guide

## Назначение

iOS-приложение для проявки фотоплёнки: журнал комплектов химии, расчёт времён этапов с учётом пробега и таймер сеанса. Один сеанс последовательно проводит несколько плёнок через этапы выбранного процесса.

## Стек

- Swift, iOS 18+, SwiftUI, Observation.
- SwiftData — комплекты химии, сессии, плёнки и снимки этапов.
- Swinject, SwinjectAutoregistration и JustKittenDI — сборка зависимостей.
- ActivityKit и WidgetKit — Live Activity и виджеты.
- Swift Testing, SwiftLint.

## Структура

- `Photochem.xcworkspace` — workspace оболочки и локального пакета Photochem. Открывать его, чтобы видеть оба набора тестов.
- `PhotochemModule/` — модуль приложения: `Model/`, `Service/`, `DI/` и `View/`.
- `PhotochemModule/Core/` — Swift-пакет расчёта времён и валидации конфигурации, с собственными тестами.
- `PhotochemModule/Tests/` — тесты приложения, сервисов и раннера.
- `PhotochemModule/Activity/` и `PhotochemModule/Widgets/` — атрибуты Live Activity и UI виджета.
- `PhotochemApp/Widgets/` — тонкое расширение виджетов.
- `PhotochemModule/Resources/Config/` — JSON-файлы процессов, включённые в ресурсы пакета. Индекс для remote-доставки генерирует `PhotochemModule/Scripts/generate_config_index.sh`; вручную его не менять.

## Архитектура и правила данных

Расчёт и валидация конфигурации находятся в PhotochemCore; сохраняй независимость ядра от SwiftUI и SwiftData. В приложении модели хранят данные, сервисы выполняют операции, ViewModel управляют состоянием экранов. Регистрации зависимостей находятся в `DI/` и сборках соответствующих экранов; следуй существующим соглашениям Swinject и JustKittenDI.

- Пробег комплекта вычисляется по всем плёнкам всех сессий, включая прерванные; отдельным счётчиком его не хранить.
- Времена этапов фиксируются при старте сессии в `StageSnapshot`. `SessionRunner` использует этот снимок; обновление конфигурации не должно менять уже начатую сессию или её историю.
- Раннер работает по абсолютному времени окончания этапа. Паузы нет; финальный сигнал заканчивается сам, затем начинается подготовка следующего этапа.
- Новый конфиг применяется только после валидации; некорректный ответ сервера не должен затирать рабочие данные.

## Проверки

Тесты ядра:

```sh
swift test --package-path PhotochemModule/Core
```

Схема `Photochem` использует `PhotochemApp/PhotochemApp.xctestplan`: в нём тесты приложения и PhotochemCore. Для запуска через Xcode используй workspace и эту схему. В CI проверки запускают workflows из `.github/workflows/` через RepoKit.

Свой конфиг линтера — `.swiftlint.yml`, он наследует базовый. Проектные исключения и правила добавляй в свой конфиг.

## Git

Semantic commits на английском: `feat:`, `fix:`, `refactor:`, `chore:`, `test:`, `docs:` и другие Conventional Commits по смыслу изменения. Изменения — в ветках задач; в `master` они попадают через PR. Не изменять версии и release-теги вручную: ими управляет release workflow.

ConvenienTimer — отдельный старый проект-референс. Не менять его в рамках работы над Photochem.
